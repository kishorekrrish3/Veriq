Verification Ledger Claim Lifecycle & Deterministic Status Model

VERIQ adheres to an honest verification model: Passing syntax checks does not prove functional correctness. A retrieved document does not validate code. Bounded tests do not prove universal truth.

VERIFIED DETERMINISTIC PASS

A specific deterministic check executed and succeeded completely. Examples: AST parsed with 0 syntax errors; Pytest test suite exited with code 0.

Evidence: Exit code 0, 0 stderr, AST node verified
SUPPORTED EVIDENCE BACKED

Available evidence supports the claim, but bounded by inherent domain limits. Examples: Tavily retrieved official documentation; empirical linting checks.

Evidence: Official doc passage, SHA-256 hash match
FAILED CHECK FAILED

A deterministic check executed and produced a failure. Examples: AST SyntaxError; non-zero pytest exit code; import traceback; disallowed path traversal.

Evidence: Exit code > 0, traceback, assertion error
UNRESOLVED INCONCLUSIVE

Evidence is missing, incomplete, or bounded by execution constraints. Examples: External service unreachable; timeout hit; test suite omitted.

Evidence: Timeout limit exceeded, missing coverage
NOT_RUN SKIPPED

The check was skipped or bypassed intentionally (e.g. earlier pipeline stage failed; feature disabled by user configuration).

Evidence: Check skipped in orchestration graph
